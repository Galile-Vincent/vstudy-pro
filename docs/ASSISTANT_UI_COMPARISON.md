# assistant-ui adoption review

Reviewed 2026-11-03 against the installed, exactly pinned `@assistant-ui/react` 0.15.32. The installation command was actually executed from `apps/desktop` in a clean shared clone at `/tmp/vstudy-assistant-setup` (the working repository had another worker's changes). First run: `npx --yes setup-agent@0.0.7 https://setup.assistant-ui.com/Ek7iZpDDAB6m`; second run: the user's literal `npx setup-agent https://setup.assistant-ui.com/Ek7iZpDDAB6m`. Full second-run output: [transcript](evidence/assistant-ui-setup.txt).

The CLI retrieved its WebSocket setup instructions and returned `status: waiting`. Its interactive approval workflow cannot finish unattended. The user's brief explicitly permits the manual path. Followed the vendor's [install guide](https://www.assistant-ui.com/install.md?items=assistant-ui), [documentation index](https://www.assistant-ui.com/llms.txt), and existing local-runtime integration. The runtime package was already installed and pinned; no global install, cloud service, telemetry, git hook, new server, scaffolding, or unrelated configuration was needed. Components below are composed directly from the installed library, rather than generated registry files.

| Feature | assistant-ui component / pattern | Previous app behavior | Verdict and resulting behavior / evidence |
| --- | --- | --- | --- |
| Composer | `ComposerPrimitive.Root`, `.Input`, `.Send`, `.Cancel` | Already used these primitives; little behavioral coverage | **Adopt**. Retains autosizing, Enter send, Shift+Enter newline and disabled/running state. Explicit composition tracking also suppresses Chinese IME confirmation Enter. Built-app IME check in `e2e/chat-controls.mjs`; component coverage checks composition events. |
| Loading | Runtime message status, coordinated Composer Cancel | Empty response while waiting | **Hybrid**. Runtime running status drives labelled thinking dots and Stop; reduced-motion CSS disables animation. No independent loading state that can drift from Stop. `/tmp/vstudy-loading.png`. |
| Message copy | `ActionBarPrimitive.Copy`, `message.isCopied` | Missing | **Adopt**. Real clipboard write and transient Copied state. Main permits sanitized clipboard writes only from the app; clipboard read remains denied. Built-app clipboard assertion. |
| User edit | `ActionBarPrimitive.Edit` and message-scoped `ComposerPrimitive` edit composer | Missing | **Adopt**. Edit opens input with Cancel edit and Save & resend. The runtime branches the edited message and starts a new call. |
| Retry / reload | `ActionBarPrimitive.Reload` | Missing | **Hybrid**. Primitive invokes the runtime; IPC adapter remembers the user turn's original selection and options. Main rebuilds context before the replayed turn, supersedes old answers for context, and records each new provider call separately. Adapter payload tests and built-app regeneration usage assertion. |
| Errors | `ErrorPrimitive.Root`, `.Message`, Reload | Error text only; no recovery | **Adopt**. Inline category and Retry. API/CLI diagnostics are reduced to safe categories; CLI stderr is never shown verbatim. Failed partial answers stay excluded from subsequent context. `/tmp/vstudy-error-retry.png`. |
| Markdown | `MessagePrimitive.Parts` text override; vendor markdown integration evaluated | Our `ReplyMarkdown` with GFM, math, sanitization, highlighting | **Hybrid / keep text renderer**. Keep the established sanitize schema, link allowlist and math behavior shared with document reading. Added code copy buttons without a second Markdown pipeline. Tables and highlighted fenced code still use existing tested rendering. |
| Scroll | `ThreadPrimitive.Viewport`, `.ScrollToBottom` | Viewport already adopted, no return control | **Adopt**. Library owns bottom anchoring and pauses autoscroll when reading above the bottom; Latest returns to live output. The library's `useThreadViewportAutoScroll` manages viewport user-scroll state. |
| Branch picker | `BranchPickerPrimitive` | No branch picker | **Keep current scope**. Runtime supports edit/regenerate branches in memory, but the database stores a linear audit history and only the latest answer remains in future context. Exposing a branch selector would imply persistent branch switching that main does not implement. This remains a limitation. |
| Thread list | `ThreadListPrimitive` / remote thread runtime | Per-document persisted Conversation dropdown | **Keep ours**. Existing dropdown enforces document ownership and uses SQLite conversations. Replacing it requires a remote-thread adapter and would duplicate controls. No extra sidebar. |
| Model selector | Vendor ModelSelector composition pattern | Native grouped select, no search | **Hybrid**. Custom searchable listbox over our provider IPC catalog, keyboard navigation, availability, Current badge, favorites and recent models in settings. Adjacent option controls come from model capabilities. Vendor runtime model suggestions cannot discover the local CLIs or own per-document settings. `/tmp/vstudy-picker-open.png`, `/tmp/vstudy-picker-search.png`, `/tmp/vstudy-composer-effort.png`. |
| Attachments / tools | AttachmentPrimitive / tool parts | Attachment-free document chat, tools disabled | **Keep attachment-free**. The imported document and selection are application context, not arbitrary message attachments. Tool UI would advertise capabilities disabled by the provider adapters. |
| Accessibility | Library primitive semantics plus application labels | Mostly native controls | **Hybrid**. Native buttons/selects, combobox/listbox state, active descendant, selected/current state, labelled copy/edit/retry/stop controls, labelled running status, keyboard search, Escape and visible focus. Full screen-reader audit remains unverified. |
| Document selection | Custom selection chip and `SelectionPreview` | Structured offsets, headings, page | **Keep ours**. Preserves document offsets and the exact selected passage through IPC and replay. |
| Usage | Custom usage chip, meter and guard | Token/cost/budget UI | **Keep ours**. Shows actual model and options alongside usage; price lookup still uses model ID alone. |

## Model and CLI evidence

Ground truth was collected without sending model inference requests:

- T3 source cloned outside this repository at `/tmp/vstudy-t3code-research`, commit `cefb544af3c98224874419198c0359b652ca3c94`. Relevant paths: `apps/server/src/provider/CodexProvider.ts` (`model/list`), `CodexChatGptModels.ts` (catalog reasoning levels), `model-manifest.json` (provider profiles), `ClaudeModelCatalog.ts`, `claudeModelOptions.ts`, and `textGeneration/ClaudeTextGeneration.ts` (effort compilation).
- `codex --help`, `codex exec --help`, `codex debug models` and cache format inspected. Curated metadata fixture: `apps/desktop/src/main/providers/fixtures/codex-models.json`. All 10 returned entries are preserved, including expected Sol/Astra/Terra/Luna and additional/legacy models. Sol/Astra/Terra report low, medium, high, xhigh, max, ultra. Luna reports low through max. Service tiers include priority; default is always available as the standard service tier.
- Claude Code 2.1.316: `claude --help` exposes `--model`, `--effort`, `--settings`, but no model-list command. Its stream-json initialize control response supplies models, aliases, resolved IDs, supported effort levels, thinking-off and fast-mode capabilities. Curated fixture: `claude-models.json`; account details and commands are intentionally excluded. It reports low through max, not ultrathink/ultracode. An initialize-only flag probe accepts max and ultracode; `--effort ultrathink` prints a warning and ignores it.
- T3 intentionally adds those two behaviors beyond the live Claude list: ultracode maps to `--effort xhigh` plus `--settings {"ultracode":true}`; ultrathink is injected into the prompt, with no invalid effort flag. These additions are labelled **T3 pattern** in the picker and scoped by the checked-in curated `claude-t3-patterns.json`. Opus/Fable expose ultracode; Sonnet/Haiku do not. Live normal effort values still take precedence.
- `agy --help` and `agy models` were run. The local CLI lists Gemini Flash high/medium/low, Claude Sonnet 4.6 Thinking, Claude Opus 4.6 Thinking and GPT-OSS 120B Medium. Antigravity discovery/streaming implementation remains the other worker's adapter; this change never edits `agy.ts`.
- Main rejects unknown option IDs/values against the selected model before invoking an adapter. Literal argv tests cover Codex `-c model_reasoning_effort=...`, `-c service_tier=...`, Claude `--effort` and session settings. No shell interpolation.
- OpenAI API declares reasoning effort only for documented o1/o3/o4-mini families; sends `reasoning_effort` to Chat Completions. Unknown model IDs, OpenAI-compatible servers and the current Anthropic API adapter expose no speculative capabilities. [OpenAI reasoning guide](https://developers.openai.com/api/docs/guides/reasoning).

## Limits to verification

No paid/authenticated inference was sent to the real providers. Discovery and local CLI flag parsing are verified; provider-side acceptance of every effort/service-tier combination is not. Static fallback model names and cached Codex names are explicitly labelled. The live catalogs can change independently of these fixtures. Durable branch switching, a complete screen-reader audit, and Anthropic API adaptive-thinking configuration remain outside this implementation. Antigravity effort declarations are also not added here because the concurrent worker owns that adapter and its ACP capability mapping; `agy.ts` was left untouched.
