## D1 — startup Keychain access

**Fixed, with a cold-start performance qualification.** Before changing the fuse, launching the existing packaged app with real Keychain access reproduced a main-thread `SecItemCopyMatching` stall. A two-second `sample` captured that stack. A simultaneous securityd stream explicitly reported an ACL prompt for PID 52871, `@vstudy/desktop Safe Storage`, and the VStudy Pro app bundle. This confirms the Chromium Safe Storage startup path rather than merely inferring it from a mock-Keychain speed comparison.

`EnableCookieEncryption` is now OFF. The renderer uses no cookies, so cookie OSCrypt initialization has no product purpose. The remaining fuses are unchanged; the packaged read-back test now asserts cookie encryption OFF alongside the other disabled fuses. **safeStorage itself remains enabled**, asynchronous, lazy and protected by the existing ten-second timeout. The only application encryption calls are in `services/secrets.ts`, on explicit save/unlock; construction, presence checks, session-only keys and startup do not encrypt or decrypt. A new literal call-sequence test covers restart with a persisted key.

Measured ad-hoc launches without `--use-mock-keychain`: first post-repackage cold launch **1.861 s**; subsequent fresh-profile launches **0.629, 0.344, 0.325 s**. Thus the original >30 s stall is removed and three repeated launches meet <1 s, but **the first post-package cold launch did not meet <1 s**. Do not report an unconditional sub-second cold-start guarantee. The after-change stack sample contains no SecItem call; securityd recorded code-signature/trust checks but no app-attributed Keychain item access before that window appeared. A securityd stream is observational evidence, not a system-wide interception proof.

Explicit save probe: **verified ordering** on the ad-hoc bundle, PID 4639. The app's own `window.isVisible()` marker and external CGWindow observation agree on **0.564 s**. In the debug securityd stream, app-attributed item-access events count **0 before visibility**, and **0 between visibility and the explicit save**. The first item event is **3 ms after save-start**, followed by `copy_matching`, decrypt and the expected Safe Storage ACL prompt. The unanswered prompt returned `errors.keychain_unavailable` after **10,013 ms**; imports and chat still completed (`smoke-result.ok=true`). Successful encryption after granting the prompt is **unverified**. With the OS request still unanswered, this probe process did not exit within the driver's 45-second wait and was terminated; quitting while a Keychain ACL request remains outstanding is a remaining lifecycle limitation, not a passing exit check. Packaged smoke no longer uses mock Keychain. Its optional, isolated `VSTUDY_KEYCHAIN_PROBE=1` path records window-visible and save-start timestamps, then attempts to save/delete a synthetic key using the real `secrets:set` IPC. It does not contact an API provider. README explains the expected save/unlock prompts and the cookie-fuse rationale.
