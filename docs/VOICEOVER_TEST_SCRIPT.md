# Manual VoiceOver test script

Status: NOT RUN. A human must record the spoken caption panel and actual focus.

**Why this is a script and not a result.** macOS VoiceOver cannot be driven reliably from automation: it needs the Accessibility/Screen-Recording permissions of a real login session, it posts speech through the system synthesiser (no API to read what it said), and its quick-nav keys are consumed before Electron sees them. I did not run VoiceOver. Everything in §1–§6 comes from the Chromium accessibility tree (CDP `Accessibility.getFullAXTree`) and axe-core; those are necessary, not sufficient. Treat every "pass" in this document as "no defect found in the tree", not "works with VoiceOver".

**Setup.** macOS 14+; current build (record the exact commit hash) run from a fresh `--user-data-dir`; System Settings → Accessibility → VoiceOver → Verbosity default; turn on *VoiceOver Utility → Visuals → Show caption panel* so what is spoken can be screenshotted. Toggle VO with ⌘F5. VO modifier ("VO") = Control+Option. Test each flow in English first, then once with the UI in 繁體中文 and once in 日本語 (voice: Mei-Jia / Kyoko) because several defects below are language-specific. Record for every step: *spoken output (caption panel), focus ring location, pass/fail*.

**Shortcut conflicts to listen for while VO is on:** `Control+Option+↑/↓` (the app's row-reorder shortcut) is the VoiceOver navigation chord and will never reach the page; the macOS-friendly alternative in the code is `⌘+Option+↑/↓`. `⌘⇧K` is unused by macOS. `Shift+F10` and the Menu key do not exist on most Mac keyboards; VoiceOver users reach the same menu with VO+Shift+M, which fires `contextmenu` and works.

**Pass criteria.** A step passes only if (a) the spoken text identifies role, name and state, (b) focus is on the element VO is describing, and (c) nothing important happens silently. Log failures against the defect IDs in §3.6 / §4.2.

## Additional regression checks

- Test list AND card view in All documents, Recent, Pinned, Unfiled, search results, and one folder. Reorder with Command+Option+Up/Down on macOS. Cross-folder reorder moves into the neighbour's folder; verify the resulting folder is understandable. Test dragging separately.
- For each pin, move, rename, delete, undo, open/back, menu/dialog close, and onboarding finish: confirm focus is on a connected control or the new view, never the page body. Name prompts must put the caret in the input; type a name containing spaces.
- Stream a 5,000-token answer. Expect one “Assistant is answering” update and one completed answer, never one announcement per token. Stop another answer, then trigger an error; listen for status and Retry. Read transcript messages to confirm author names.
- In the reader, Tab to paragraph actions, activate with Space/Enter, then type in the composer. Use VoiceOver text-selection commands for an arbitrary sentence and Command+Shift+K.
- Test each language in light/dark at 1200, 900, and 720 physical pixels and 200% zoom. At 720/200% verify single-column content and sidebar toggle without horizontal scrolling.
- Toggle Reduce Motion, Reduce Transparency, Increase Contrast and Differentiate Without Color while running; record both immediate response and response after restart. Test forced colours on a supported platform separately.

Record: date, macOS version, app commit/build, UI language, voice, theme, window width, zoom, task, expected speech, actual speech, focused element, screenshot path, pass/fail, finding ID. A passing axe/tree check does not establish a VoiceOver pass.
