## Evidence and limitations

Failing-before behavioral probes were run and committed for findings 1, 2 (publication), 3 (awaiting producer), 4, 5, 6, 9, option-validation and nullable-size pagination. New ownership/discovery/backfill APIs initially failed at missing-module/export boundaries; those red runs are not equivalent to reproducing all old process/migration behaviors. Supplemental tests for enclosing rollback, regeneration cancellation, multi-model usage faults, origin binding, descendant liveness, source disk-full, seeded usage and interruption were added after the initial fixes. This does not satisfy a strict claim that every supplemental scenario was committed and executed failing before any implementation change.

Actual forced process-kill/power-loss, output-rename/physical-purge/checkpoint/backup disk exhaustion and OS Keychain races were not exhaustively exercised. Trigger ABORT, enclosing ROLLBACK and fake encryption are fault simulations, not power-failure or real Keychain evidence. The native PID assertion covers children observed before quit; it is not a system-wide orphan-process census. Discovery PID tests separately cover a real descendant. `providers.test.ts` also reproduces a CLI parent exiting on TERM while its descendant ignores TERM; cleanup now always kills the remaining group after parent close. That test failed before the fix and passes afterward. Trigger-faulted multi-model usage rollback is tested in-memory; the native restart test covers interrupted streaming rather than a trigger-faulted restart.
